# Documentation Folder Conventions

이 프로젝트(또는 이 컨벤션을 쓰는 프로젝트들)는 문서 폴더를 용도별로 분리한다.

## `document/` 폴더 (한글)
- 목적: 진행상황, 세션별 상태, 트러블슈팅/포스트모템을 사람(개발자 본인)이 나중에 읽기 위한 기록
- 언어: 한글
- 주요 파일:
  - `document/PROJECT_STATUS.md`: 현재 진행 중인 세션 로그 및 프로젝트 상태
  - `document/FINDINGS_*.md`: 트러블슈팅 노트, 실험, 발견 사항

## `docs/` 폴더 (영어)
- 목적: 다른 AI 에이전트(Claude Code 등)가 세션이 바뀌어도 이어서 참고할 기술 스펙 — 아키텍처 요약, 설계 스펙, API, 프로젝트 컨텍스트
- 언어: 영어
- RAW로 미러링하지 않는다. 이건 "사람이 읽을 기록"이 아니라 "에이전트가 다음 세션에서 쓸 컨텍스트"라서 RAW(사람이 나중에 참조할 원본 사료) 성격과 다르다.

## 작업 규칙
- 작업 보고서, 진행상황 요약, 트러블슈팅 로그를 생성할 때 → 한글로 작성, `document/`에 저장
- 다른 AI 에이전트가 참조할 기술 스펙, 코드베이스 설명, API 매뉴얼을 생성할 때 → 영어로 작성, `docs/`에 저장

## document/ 자체를 언제 쓰는가
지금까지는 "보고서를 만들 때 document/에 저장하라"만 있었고, "언제 보고서를 만드는가"가 빠져 있었다. 아래 시점에 document/PROJECT_STATUS.md(또는 필요시 FINDINGS_*.md)를 작성/갱신한다:

1. **세션이 끝나갈 때** — 대화가 마무리되는 분위기이거나, 사용자가 다음에 이어서 할 것을 언급하면, 지금까지 진행 상황을 PROJECT_STATUS.md에 갱신한다.
2. **중요한 결정이 나거나 방향이 바뀔 때** — 설계 선택, 트러블슈팅으로 원인을 확정한 순간 등. 사소한 코드 수정 하나하나까지 기록하지 않는다.
3. **컨텍스트가 길어져 요약/압축이 필요해질 때** — 대화가 매우 길어지는 시점에, 지금까지 흐름을 PROJECT_STATUS.md에 남겨 다음 세션이 이어받을 수 있게 한다.
4. **사용자가 명시적으로 요청할 때** — "진행상황 정리해줘", "여기까지 기록해줘" 등.

## PROJECT_STATUS.md 크기 관리
무한정 이어붙이지 않는다. 파일이 길어지면:
- **최근 항목(대략 최근 2~3세션 분량)은 그대로 유지**한다.
- **그보다 오래된 항목은 날짜별 짧은 요약으로 압축**해 하나로 합친다 — 세부 내용을 다 지우는 게 아니라, 여러 옛날 항목을 한 문단짜리 요약으로 묶는다.
- 세부 트러블슈팅 기록이 필요하면 FINDINGS_*.md로 분리하고, PROJECT_STATUS.md에는 그 파일로의 링크만 남긴다.
- 이미 RAW로 미러링된 옛 항목은 PROJECT_STATUS.md에서 압축해도 안전하다 — RAW에 원본이 남아있으므로 정보 손실이 아니다.

## document/ → RAW 미러링 트리거
매번 document/ 파일을 건드릴 때마다 미러링하지 않는다. 아래 세 가지 상황에서만 트리거된다:

1. **세션 종료/만료 시** — 그 세션에서 `document/PROJECT_STATUS.md` 또는 `document/FINDINGS_*.md`가 갱신됐다면, 세션이 끝나는 시점에 그 내용을 RAW로 미러링한다.
2. **트러블슈팅이 일정량 쌓였을 때** — `document/FINDINGS_*.md`에 새로운 트러블슈팅/실험 기록이 추가되어 "사람이 나중에 참조할 만큼 정리된" 상태가 됐다고 판단되면 그 시점에 미러링한다. 매 줄 수정마다 하지 않는다.
3. **사용자가 명시적으로 요청할 때** — "이거 정리해줘", "RAW로 넘겨줘" 등.

즉 document/ 자체는 진행 중에는 로컬에서만 계속 갱신되는 작업 로그이고, RAW 미러링은 "이 내용이 완결되거나 사람이 다시 볼 만한 형태가 됐을 때"만 일어나는 승격 이벤트다. 로컬 document/ 파일은 그대로 유지하고 RAW는 추가 사본일 뿐이다.

## 미러링 실행 방법 (실제 옵시디언 연결)
"RAW로 미러링한다"는 말이 실제로 하는 일은 다음과 같다 — 미루지 말고 이 순서로 실행한다:

1. obsidian_get_note로 볼트 루트의 `BellFollow/Wiki.md`를 읽는다 (아직 안 읽었으면). RAW 파일명 규칙, frontmatter 스키마(source/captured/status/project/tags), project 필드 채우는 법(git 레포명, 없으면 사람에게 확인)이 여기 있다.
2. document/ 파일(PROJECT_STATUS.md 또는 FINDINGS_*.md)의 내용을 obsidian_write_note로 `BellFollow/RAW/YYYY-MM-DD_<slug>.md`에 새로 생성한다. Wiki.md가 정한 frontmatter를 그대로 채운다. source 필드에는 로컬 document/ 파일 경로를 적는다.
3. 저장 전, obsidian_search_notes로 같은 source(같은 document/ 파일)를 이미 미러링한 RAW가 있는지 확인한다 — 있으면 새로 만들지 말고 그 사실을 보고한다 (이미 미러링된 세션 로그를 중복 저장하지 않는다).
4. 로컬 document/ 파일은 절대 건드리지 않는다 — RAW 생성만 하고 끝난다.
